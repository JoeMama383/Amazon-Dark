======================================================================

BASE
----

DEVICE EVIDENCE FROM v7.347
---------------------------
The supplied transition archive contains 107 CART_STRIP_OWNER records and repeated native loading cycles.

The prior leading theories are disproven:
- exactHookSeen becomes true and remains true;
- global mount witness also sees AWLoadingIndicatorBarView;
- cartTab latch and the live selected state become true;
- the bar receives an opaque black 430x5 AmazonDarkCartLoadingBar7345 layer;
- coverHidden=false, coverOpacity=1, coverBG=[0,0,0,1], coverZ=FLT_MAX;
- repeated fresh bar mounts receive the cover again during their didMoveToWindow/layout lifecycle.

Therefore the persistent physical strip is not explained by a missing exact hook or a permanently false Cart gate.

ROOT CAUSE
----------
The same native frames expose the overlooked renderer:

AWLoadingIndicatorFullScreenModalBar
  -> AWLoadingIndicatorWidgets_BkgView
       layerClass=CAGradientLayer
       background/presentation background=black after v7.130 ownership
       authored gradient colors still approximately:
         [0.929,0.929,0.929,1]
         [0.871,0.871,0.871,1]
  -> AWLoadingIndicatorWidgets_Indicator
       -> AWLoadingIndicatorBarView (430x5, content-backed)
          -> AWLoadingIndicatorWidgets_HighlightView (860x5 CAGradientLayer)

v7.130 forced BkgView's UIView/CALayer background black and inserted AmazonDarkOLEDBacking7130 BELOW child/content rendering, but it never changed CAGradientLayer.colors. Thus the exact surface could still draw an authored light gradient above the black background/backing.

v7.345/v7.346 then added a black sublayer inside AWLoadingIndicatorBarView. That cover can dominate the bar's own subtree, but BkgView is a sibling renderer under the full-screen loading host. A child zPosition cannot guarantee dominance over a separate sibling subtree. This explains how the probe can simultaneously report a valid black bar cover and the user can still see a bright strip.

v7.348 PRODUCTION REPAIR
------------------------
1. Complete the retained v7.130 BkgView contract.
   - If exact AWLoadingIndicatorWidgets_BkgView qualifies as the existing app-loading surface, and its layer is CAGradientLayer, replace its colors array with the same number of OLED-black CGColors.
   - Keep existing OLED UIView/layer background and backing layer.
   - Reassert on didMoveToWindow/layout and on owned background writes.

2. Own the exact Cart bar plane, not only an overlay.
   - While cartTab is selected, AWLoadingIndicatorBarView itself gets OLED background/layer background.
   - Clear only the transient bar layer.contents.
   - Retain AmazonDarkCartLoadingBar7345 as a defensive black seal.

3. Seal exact native descendants during Cart loading.
   - AWLoadingIndicatorWidgets_Indicator -> OLED floor.
   - AWLoadingIndicatorWidgets_HighlightView -> OLED floor; if CAGradientLayer, all authored gradient colors become OLED black.
   - No frame, bounds, transform, animation, duration, or loading lifecycle is modified.
